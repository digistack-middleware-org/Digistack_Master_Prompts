Purpose
-------
A permanent, fully-worked interview reference book derived entirely from
P01, P02, and P03 — every question, scenario, troubleshooting case,
runbook, and mock interview must map back to a specific version/component
actually built in this project. This is the source material P03.1's
drills are practiced against, not a duplicate of P03.1's checklist.

Deployment Model
------------------
Zero new banking functionality, zero new infrastructure — documentation/
reference artifacts only, same as P03.1. Produced sprint by sprint, one
chapter's worth of content at a time, in the format already agreed:
short spoken-style answer + why-it's-asked + implementation reference +
architecture tie-in + real example + follow-ups + mistakes + best
practices.

Placement Note
------------------
Suffix Part, same mechanism as P03.1. Sits between P03 and P03.1 in
reading order (P03 → P03.2 → P03.1 → P04). No version numbers (v1–v78)
are touched.

Version 1 — Chapter 1: Enterprise Interview Questions
------------------------------------------------------------
Objective: Build the full interview question bank, organized by topic
area, each fully worked in the agreed format.

Sprint 1 — Architecture & Design Decisions
(CBS single-EAR, Portal/CBS split, Payment Hub Saga pattern, Reporting
Service tradeoff, Card Portal on WAS vs. Tomcat, database evolution)

Sprint 2 — Request Flow & Core Transactions
(Fund Transfer end-to-end, Deposit/Withdraw, Balance Inquiry, NEFT vs.
IMPS, BOD/EOD)

Sprint 3 — Clustering & High Availability
(DMgr/node federation, session replication, sticky sessions vs.
replication, plugin failover, Core Groups)

Sprint 4 — JMS / SIBus / IBM MQ
(producer/consumer/MDB pattern, DLQ, SIBus vs. MQ decision, CHLAUTH,
Messaging Engine failover)

Sprint 5 — Security
(MFA/OTP, account lockout, LTPA/SSO, mTLS, role-based authorization,
CSRF/XSS)

Sprint 6 — Monitoring, Migration & Multi-Region (capstone)
(Operations Dashboard → Prometheus/Grafana retirement, WebSphere version
migration, multi-region data residency, DR/RPO-RTO)

Deliverable: Full Chapter 1 question bank, ~30-40 questions across 6
sprints, each in the agreed short-answer format.

DigiStack components (IHS, LB, WAS Cell, DMgr, Node Agents, Cluster

Sprint 1 — Cluster & Node-Level Scenarios
Sprint 2 — Messaging Scenarios (JMS/SIBus/MQ)
Sprint 3 — Security & SSL Scenarios
Sprint 4 — Database Scenarios
Sprint 5 — Multi-App / Cross-Service Scenarios (Card Portal ↔ ATM, Branch
Portal BOD/EOD, Payment Hub ↔ CBS)
Sprint 6 — Capstone: Combined/Cascading Failure Scenario

Deliverable: Full scenario bank, each scenario tied to a specific
component and a specific P01/P02/P03 version.

Version 3 — Chapter 3: Production Troubleshooting
------------------------------------------------------------
Objective: Full troubleshooting cases in the fixed shape: Production
Problem → Business Impact → Symptoms → Request Flow → Components
Involved → Logs to Check → Commands to Execute → Investigation Process →
Root Cause → Resolution → Prevention → Lessons Learned.

Sprint 1 — WAS/Cluster Failures (Node Agent down, DMgr down, cluster
down, hung threads, OOM)
Sprint 2 — JDBC / Database Failures
Sprint 3 — Messaging Failures (MQ queue full, DLQ growth, SIBus ME
failover)
Sprint 4 — SSL / Plugin / Deployment Failures
Sprint 5 — Application-Layer Failures (session loss, security event
detection false positive, CIF/Aadhaar verification failure)
Sprint 6 — Capstone: Multi-symptom cascading incident (mirrors RACI01's
Site Failure category)

Deliverable: Full troubleshooting case bank, cross-referenced against
RACI01's RACI matrix for ownership at each step.

Version 4 — Chapter 4: Enterprise Production Runbooks
------------------------------------------------------------
Objective: Fully written runbooks (Purpose, Scope, Prerequisites,
Step-by-Step Procedure, Validation, Rollback, Post-Implementation Checks)
for real DigiStack operations.

Sprint 1 — Deployment & Rollback (EAR deploy, rollback, blue-green)
Sprint 2 — Cluster/Node Operations (cluster member restart, node sync,
plugin regeneration)
Sprint 3 — Messaging & Database Recovery (MQ recovery, JMS queue
recovery, DB failover)
Sprint 4 — Security Operations (SSL certificate renewal, emergency
change)
Sprint 5 — Incident Response (JVM OOM response, DR runbook)
Sprint 6 — Capstone: BOD/EOD Operations + Production Release runbook

Deliverable: Full runbook library, one runbook per operation listed in
the original request.

Sprint 3 — Change Management + Incident Handling round
Sprint 4 — Root Cause Analysis + Performance Tuning round

per round, plus one full combined capstone run.
