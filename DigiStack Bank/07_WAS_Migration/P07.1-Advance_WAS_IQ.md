Purpose
-------
Same discipline as P03.2, one tier up: a permanent, fully-worked interview
reference book derived entirely from P04, P05, P06, and P07 — every
question, scenario, troubleshooting case, runbook, and mock interview must
map back to a specific version/component actually built in those four
Parts. This is not a repeat of P03.2's banking-app content; P03.2 owns
P01–P03 (the application), this file owns P04–P07 (operating, recovering,
scaling, and migrating that same application).

Boundary Note (P03.2 vs. P07.1)
------------------------------------
- P03.2 — CBS, Payment Hub, Fund Transfer, channel simulators, the
  9-application topology itself.
- P07.1 — everything done *to* that unchanged topology: observability
  (P04), HA/DR (P05), multi-region (P06), platform migration (P07).
No content is duplicated between the two; a question about Fund
Transfer's request flow belongs in P03.2, a question about how Fund
Transfer's SLO is measured belongs here.

Deployment Model
------------------
Zero new banking functionality, zero new infrastructure — documentation/
reference artifacts only, same as P03.1/P03.2. Produced sprint by sprint,
one chapter's worth of content at a time, in the agreed format: short
spoken-style answer + why-it's-asked + implementation reference +
architecture tie-in + real example + follow-ups + mistakes + best
practices.

Placement Note
------------------
Suffix Part, same mechanism as P03.1/P03.2. Sits between P07 and P08 in
reading order (P07 → P07.1 → P08). No version numbers (v1–v78) are
touched; this produces no deployables.

Prerequisite
------------------
P07 Completion Checkpoint satisfied — migrated WAS platform live across
all three regions. Assumes the candidate actually built P04–P07, not
merely read about them, same standing assumption P03.1 makes for P01–P03.

Version 3 — Chapter 3: Production Troubleshooting
------------------------------------------------------------
Objective: Full troubleshooting cases in the fixed shape: Production
Problem → Business Impact → Symptoms → Request Flow → Components
Involved → Logs to Check → Commands to Execute → Investigation Process →
Root Cause → Resolution → Prevention → Lessons Learned.

Sprint 1 — Observability Failures (missing traces, broken PMI/JMX
scrape, log pipeline gap)
Sprint 2 — HA/DR Failures (failed failover, replication lag, stale DR
site)
Sprint 3 — Multi-Region Failures (GSLB misroute, cross-region cert
mismatch, LTPA rejection)
Sprint 4 — Migration Failures (deprecated API breaking an EAR,
JNDI/JDBC resource not resolving post-migration, stuck canary rollout)
Sprint 5 — Capacity/Performance Failures (SLO breach, saturation not
caught by alerting)
Sprint 6 — Capstone: Multi-region + migration cascading incident,
cross-referenced against RACI01's Site Failure category

Deliverable: Full troubleshooting case bank, cross-referenced against
RACI01's RACI matrix and P05 v36's Failure Type Taxonomy.
