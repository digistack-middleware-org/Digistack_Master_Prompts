Purpose
-------
Same discipline as P03.2/P07.1/P08.1, one tier up: a permanent,
fully-worked interview reference book derived entirely from P09 — every
question, scenario, troubleshooting case, runbook, and mock interview
must map back to a specific version/phase actually built in that Part.
P09 covers AWS Foundation & Hybrid Connectivity (Phase-1), Lift & Shift
(Phase-2), Platform Modernization (Phase-3), and Full AWS Migration
(Phase-4) — this file is the interview material for exactly that,
nothing else.

Boundary Note (P09.1 vs. prior Interview Parts)
------------------------------------------------------
- P03.2 — the application itself (CBS, Fund Transfer, channel simulators).
- P07.1 — operating/recovering/scaling/migrating that application
  on-prem (observability, HA/DR, multi-region, WAS platform migration).
- P08.1 — how the application/platform gets built, tested, and deployed
  (Git, CI/CD, IaC, deployment automation).
- P09.1 — how the same unchanged application moves onto AWS (hybrid
  connectivity, lift-and-shift, managed-service modernization, cutover,
  cloud DR/ops/security). A question about RDS Multi-AZ failover belongs
  here; a question about what Fund Transfer does belongs in P03.2; a
  question about the Jenkins pipeline that deploys it belongs in P08.1.

Deployment Model
------------------
Zero new banking functionality, zero new infrastructure — documentation/
reference artifacts only, same as every prior Interview Part. Produced
sprint by sprint, one chapter's worth of content at a time, in the agreed
format: short spoken-style answer + why-it's-asked + implementation
reference + architecture tie-in + real example + follow-ups + mistakes +
best practices.

Placement Note
------------------
Suffix Part, same mechanism as P03.1/P03.2/P07.1/P08.1. Sits between P09
and P10 in reading order (P09 → P09.1 → P10). No version numbers (v1–v78)
are touched; this produces no deployables.

Prerequisite
------------------
P09 Completion Checkpoint satisfied — DigiStack Bank fully AWS-native
(EC2 → RDS for PostgreSQL, S3, hybrid SQS/SNS+MQ, IAM/Secrets Manager/
KMS/ACM), part9-release tag applied, all three regions cut over with
on-prem fully decommissioned. Assumes the candidate actually built P09,
not merely read about it, same standing assumption every prior Interview
Part makes.

IAM, EC2, RDS, S3, SQS/SNS, IBM MQ hybrid, Route 53/GSLB, Secrets

DNS cutover not propagating cleanly, cost/tagging gap discovered post-cutover)
Sprint 6 — Capstone: Combined region-level AWS DR failover during an
active cost/compliance audit

Deliverable: Full scenario bank, each tied to a specific component and a
specific P09 version/phase.

Version 3 — Chapter 3: Production Troubleshooting
------------------------------------------------------------
Objective: Full troubleshooting cases in the fixed shape: Production
Problem → Business Impact → Symptoms → Request Flow → Components
Involved → Logs to Check → Commands to Execute → Investigation Process →
Root Cause → Resolution → Prevention → Lessons Learned.

Sprint 1 — Networking/IAM Failures (VPC route misconfiguration, IAM
least-privilege breaking a legitimate cross-account call)

Sprint 3 — Managed-Service Failures (RDS failover leaving a connection
pool stale, S3 replication lag breaching cross-region durability
expectation)
Sprint 4 — Messaging/Security Failures (SQS message loss vs. IBM MQ's
guaranteed delivery expectation, ACM cert renewal not propagating to ALB)
Sprint 5 — Cutover Failures (canary stuck at 25%, DNS TTL causing stale
routing during cutover)
Sprint 6 — Capstone: Multi-phase cascading failure spanning
lift-and-shift + modernization + cutover boundaries

Deliverable: Full troubleshooting case bank, cross-referenced against
P09's own Completion Checklist and RACI01's Cloud/Platform Team row.
