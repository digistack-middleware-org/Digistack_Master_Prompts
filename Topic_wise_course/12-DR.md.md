# 🛡️ Course 8 — Transactions, Patching, Backup & DR — Zero to Expert
## ~30 Days @ 1 hr/day | The "Trusted Senior" Skills | Ox Alpha | WAS 8.5.5/9.0 ND | BankCell01

> **Format:** Theory 80% → Banking Scenario 15% → Interview 5% (Basic→Expert)
> **Every topic:** Admin Console steps + wsadmin steps
> **Lab:** BankCell01 — DMGR, Node01/Node02, PaymentCluster, DRCell01

---

## 📗 PHASE 1 — TRANSACTION SERVICE (Days 1–8)

| Day | Topic |
|---|---|
| **1** | Transactions 101: ACID explained via a funds-transfer (debit + credit must both happen) |
| **2** | Local vs global (XA) transactions; two-phase commit — the coordinator story |
| **3** | WAS Transaction Service: transaction logs (tranlog), where they live, why size matters |
| **4** | Transaction timeouts: total transaction, client inactivity, max in-process — console + wsadmin |
| **5** | **XA recovery:** what happens when a server dies mid-payment — recovery log replay walkthrough |
| **6** | HeuristicCompletion states (heuristic hazard/committed/rolled back) — how to resolve safely |
| **7** | WSVR/WTRN error codes; enabling transaction tracing |
| **8** | **LAB: Kill a server mid-XA transaction, then recover it properly** |

---

## 📗 PHASE 2 — PATCHING & MAINTENANCE (Days 9–16)

| Day | Topic |
|---|---|
| **9** | IBM Installation Manager: install, update, rollback — how WAS 8.5/9.0 patching actually works |
| **10** | Fixpacks vs iFixes vs feature packs — terminology decoded |
| **11** | **Correct patch order: DMGR → nodes (federated) → servers** — and why wrong order corrupts sync |
| **12** | Pre-patch checklist: backup, disk space, in-flight transactions, DMGR down, node agents down |
| **13** | Patching via CLI (`imcl`) — scripted & silent installation |
| **14** | Java SDK upgrades for WAS (`updatesdk`), verifying Java version per profile |
| **15** | Post-patch validation: versionInfo, start sequence, app smoke tests |
| **16** | **LAB: Full mock fixpack weekend plan with rollback rehearsal** |

## 📗 PHASE 3 — BACKUP & RESTORE (Days 17–21)

| Day | Topic |
|---|---|
| **17** | `backupConfig` / `restoreConfig` — full vs config-only, what's included (and what's NOT!) |
| **18** | What lives outside config: installedApps, file registry, LTPA keys, tranlogs — backup these too |
| **19** | Backing up keystores, security.xml, J2C passwords (encoded!) — the restore nightmare prevention |
| **20** | Scheduled backups + retention — the script every bank needs |
| **21** | **LAB: Backup BankCell01, break it, restore it fully — prove it works** |
